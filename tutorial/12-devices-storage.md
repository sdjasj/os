# 第 12 章：设备、驱动与存储介质

> 对应讲义：[第 22 讲](../sources/notes/lect22.md)、[第 23 讲](../sources/notes/lect23.md)，配套实验：[device_file.c](../examples/device_file.c)

I/O 设备是计算世界与物理世界的桥。设备千差万别，但常见交互骨架相似：软件写控制寄存器，设备异步工作，通过中断报告事件，并用 DMA 批量搬运数据。

## 12.1 一个最小设备模型

可把设备抽象为几个寄存器和内部状态机：

```text
status register   ← 软件读：忙/完成/错误
command register  ← 软件写：开始某项操作
data/address regs ← 参数或 DMA 缓冲区地址
interrupt line    → 设备通知 CPU
```

寄存器可以通过端口 I/O，也可以映射到物理地址空间（MMIO）。MMIO 访问具有设备语义，不能像普通内存那样随意缓存或重排；内核用体系结构专用 accessor 和 memory barrier。

GPIO 控制 LED 是最小例子：把某一位配置为输出，再写 0/1。串口、键盘和磁盘虽然协议复杂，本质仍是软件与设备状态机交换控制和数据。

## 12.2 轮询、中断与 DMA

- **轮询**：CPU 反复读状态；简单、低延迟可控，但浪费计算资源。
- **中断**：设备完成后通知 CPU；空闲时高效，但每次中断有固定成本。
- **DMA**：设备直接在内存与设备间搬运大块数据，CPU 只准备描述符并处理完成事件。

高性能设备会批处理、中断合并，甚至在高负载下重新使用轮询，因为每个小包一次中断会形成 interrupt storm。网络 NAPI、NVMe 多队列都体现了“根据 workload 切换 fast path”。

DMA 也引出安全问题：设备拿到物理地址后可能读写任意内存。IOMMU 为设备提供类似页表的地址转换与隔离，虚拟机直通设备时尤其重要。

## 12.3 总线与设备发现

总线提供寻址、发现、配置和传输协议。PCIe 把设备组织成层次结构，操作系统枚举配置空间、分配 BAR 和中断向量，再把匹配设备交给驱动。现代 GPU/NPU 自身就是带处理器、内存和固件的计算系统。

CXL 在 PCIe 物理基础上扩展缓存一致和内存语义，可能让加速器与主机更紧密共享内存，但一致性、拓扑和故障管理不会因此消失。

## 12.4 驱动把设备变成操作系统对象

UNIX 常通过设备文件暴露驱动。运行：

```bash
./examples/device_file
strace -e trace=openat,read,ioctl,fstat ./examples/device_file
```

示例从 `/dev/zero` 读取全零字节，并对终端调用 `TIOCGWINSZ`：

```c
int fd = open("/dev/zero", O_RDONLY);
read(fd, bytes, sizeof(bytes));
ioctl(STDOUT_FILENO, TIOCGWINSZ, &window);
```

普通 `read/write` 适合流式数据，`ioctl` 承载无法自然表达的设备控制。后者扩展灵活却类型不透明、兼容难；现代子系统也会使用 netlink、sysfs、专用系统调用或共享 ring。

`mmap` 可把设备缓冲区或寄存器暴露给用户态，减少复制，却要求严格校验范围和同步。把驱动逻辑移到用户态能改善隔离与开发体验，但中断、DMA 和权限仍需内核/IOMMU 支持。

## 12.5 存储设备应看哪些指标

不论磁带、磁盘、光盘还是 SSD，都可问：

- 容量与单位成本；
- 顺序/随机读写带宽；
- 单次访问延迟和队列深度；
- 最小读、写、擦除单位；
- 耐久性、断电行为与错误率；
- 是否可原地覆盖；
- 内部缓存何时真正落到介质。

操作系统向上常提供“编号固定大小块的数组”这一抽象，把不同介质的机械/电子细节留给设备固件与块层。

## 12.6 磁盘：位置决定延迟

HDD 的随机访问包含寻道和旋转等待，远慢于顺序传输。操作系统/控制器会排序请求，文件系统倾向把相关数据连续布局；队列太深虽然提高吞吐，也会增加请求延迟。

调度算法必须兼顾吞吐、公平和 deadline。今天设备内部也会重排，主机看到的逻辑块位置不完全等于物理位置，但顺序 I/O 仍常更友好。

## 12.7 NAND Flash：不能原地覆盖

Flash 通常按 page 读写、按更大的 erase block 擦除，而且擦除次数有限。更新逻辑块时，SSD 往往：

1. 把新版本写到空闲物理页；
2. 更新逻辑块到物理页的映射；
3. 后台垃圾回收搬走仍有效页；
4. 擦除回收整个块。

Flash Translation Layer（FTL）把这些过程伪装成可随机覆盖的块设备。代价是写放大、垃圾回收尾延迟和映射元数据一致性。TRIM 告诉 SSD 某些逻辑块已无用，帮助回收。

磨损均衡让擦除分散；过量预留提供回收空间。消费级设备的断电保护和 flush 语义可能不同，数据库不能仅凭“`write` 返回成功”推断持久化。

## 12.8 Linux 块 I/O 路径

上层文件系统把页面/块请求组织成 bio，块层合并、拆分并提交到设备队列，驱动转换成硬件命令，完成后通过中断/轮询回调。多队列设计让每 CPU/硬件队列减少全局锁竞争。

```text
read/write/mmap
   ↓ page cache / filesystem
   ↓ bio / block multi-queue
   ↓ driver / controller queue
   ↓ HDD or SSD firmware
```

一次应用写入可能停在 libc、页缓存、块层、控制器 DRAM 或介质中的任一层。下一章讨论如何用协议跨越这些缓存建立崩溃一致性。

## 12.9 常见误区

- 设备文件内容真的“存放在 `/dev`”：目录项只是访问驱动对象的入口。
- 中断一定比轮询快：高事件率下批量轮询可能更高效。
- DMA 不经过 CPU，所以自动安全：CPU 仍配置描述符，IOMMU 和缓存一致性很关键。
- SSD 没有机械头，所以所有访问等价：并行通道、FTL、GC 和写放大会造成显著差异。
- `write` 成功等于断电不丢：数据可能只到内核或设备易失缓存。
- 块大小就是 NAND page 大小：主机逻辑块与内部物理组织由 FTL 解耦。

## 12.10 自测与实验

1. 修改 `device_file` 读取 `/dev/urandom`，比较设备对象的共同接口和不同语义。
2. 用 `dd` 或自写程序比较顺序与随机 I/O；避免在重要盘上做破坏性写测试。
3. 为什么 DMA ring 中更新描述符后、通知设备前常需要 memory barrier？
4. 深队列如何同时提高 SSD 吞吐并恶化单请求延迟？
5. 一次 `fsync` 从应用到介质可能经过哪些层，每层需要提供什么保证？
