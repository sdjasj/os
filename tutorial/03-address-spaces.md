# 第 3 章：地址空间——每个进程都以为自己独占内存

> 对应讲义：[第 6 讲](../sources/notes/lect06.md)，配套实验：[mmap_cow.c](../examples/mmap_cow.c)

虚拟内存不只是“内存不够时换页”。它首先是一种命名、隔离和保护机制：每个进程用自己的虚拟地址命名内存，页表决定这些名字当前对应什么物理资源。

## 3.1 指针保存的是虚拟地址

进程执行一次内存访问时，硬件大致完成：

```text
虚拟地址 = 虚拟页号 VPN + 页内偏移
                    │
              TLB / 多级页表
                    ↓
物理地址 = 物理页号 PPN + 同一页内偏移
```

页表项除物理页号外还有 `present`、可读、可写、可执行、用户可访问、dirty、accessed 等位。TLB 缓存近期翻译，否则每次访存都要额外访问多级页表。

两个进程可以打印出相同指针 `0x7fff...`，却映射到不同物理页；同一物理页也可被映射到多个进程或多个虚拟地址。于是“指针就是内存条地址”的直觉会出错。

## 3.2 一个典型地址空间

```text
高地址  ┌──────────────────────┐
        │ 内核保留/不可访问     │
        ├──────────────────────┤
        │ 用户栈 ↓              │  guard page 防止无声越界
        │ mmap 区、共享库        │
        │ 堆 ↑                  │  malloc 常从这里或 mmap 取页
        │ .bss / .data          │
        │ .rodata / .text       │
低地址  └──────────────────────┘
```

这只是布局惯例。ASLR 会随机化栈、库、堆和 PIE 主程序的位置；链接器脚本、加载器和 `mmap` 都能改变布局。用下面的命令看事实：

```bash
cat /proc/self/maps
pmap -x $$
readelf -l ./examples/mmap_cow
```

ELF 的 segment 描述加载时需要建立的映射；section 更多服务于链接和调试。不要把两者混为一谈。

## 3.3 缺页不是一定出错

CPU 发现页表不能完成访问就产生 page fault，内核根据映射语义决定：

- 首次访问匿名页：分配清零物理页；
- 访问尚未读入的文件页：从页缓存/设备装入；
- 写 COW 页：复制后改为可写；
- 页暂时被换出：从 swap 读回；
- 权限或地址非法：向进程发送 `SIGSEGV`/`SIGBUS`。

所以缺页是一种通用的延迟兑现机制。只有内核无法合法满足访问时，才表现为程序崩溃。

## 3.4 mmap：直接编辑地址空间

核心接口：

```c
void *p = mmap(NULL, length,
               PROT_READ | PROT_WRITE,
               MAP_PRIVATE | MAP_ANONYMOUS,
               -1, 0);
if (p == MAP_FAILED) perror("mmap");
munmap(p, length);
```

关键维度彼此独立：

| 维度 | 选择 | 含义 |
|---|---|---|
| 来源 | 匿名 / 文件 | 清零页，或由文件内容支撑 |
| 可见性 | `MAP_PRIVATE` / `MAP_SHARED` | 修改走 COW，或对同一映射可见 |
| 权限 | `PROT_READ/WRITE/EXEC` | CPU 对访问进行硬件检查 |
| 时机 | eager / demand paging | 现在准备物理页，或首次访问再准备 |

运行示例：

```bash
./examples/mmap_cow
```

父子进程中的两个指针数值相同。子进程写 `MAP_PRIVATE` 后，父进程仍读到 10；写 `MAP_SHARED` 后，父进程读到 77：

```c
*private_page = 99;  // 子进程得到私有物理副本
*shared_page = 77;   // 父子观察同一物理页
```

这个实验同时说明“地址相同”与“对象相同”是两回事。

## 3.5 文件映射、页缓存与持久化

文件映射把文件偏移区间变成可寻址内存。读取可能命中 page cache，也可能触发缺页 I/O。`MAP_SHARED` 的脏页最终可回写文件，但“内存里已经改了”不等于“断电后一定存在”；需要根据一致性需求调用 `msync`/`fsync`，并理解文件系统和设备缓存。

`MAP_PRIVATE` 对文件的修改只进入进程的 COW 页，不回写原文件。它常用于加载可执行文件和共享库：代码页可跨进程共享，发生重定位或写入的数据页才私有化。

## 3.6 地址空间是一种能力边界

默认隔离不意味着绝对不可观察。调试器、性能分析器和系统管理工具在权限允许时可以通过 `ptrace`、`process_vm_readv/writev` 或 `/proc/PID/mem` 访问目标进程。共享内存则是双方主动建立的共同映射。

这解释了课程中的“金手指”例子：先扫描目标进程内存找到数值，再修改它。现代游戏和安全软件会采用完整性检查、权限隔离、硬件辅助保护甚至外部设备；攻防本质是不断重画可信边界。

## 3.7 实用保护技巧

- **W^X**：页面通常要么可写，要么可执行，降低注入数据后直接执行的风险。
- **guard page**：在栈或特殊缓冲区旁放不可访问页，让越界尽快崩溃。
- **ASLR + PIE**：随机化代码和数据位置，提高利用漏洞的难度，但不修复漏洞。
- **最小权限调试**：生产环境限制 ptrace、core dump 和 `/proc` 可见性。
- **长度与溢出检查**：`size * count` 在交给 `mmap`/`malloc` 前也可能整数溢出。

## 3.8 常见误区

- “64 位进程有 16 EiB 可用内存”：虚拟地址位数、内核布局、资源限制和页表成本都使实际范围小得多。
- “申请成功就已经占用同等物理内存”：过量承诺和 demand paging 可能把分配推迟到首次写入。
- “`free` 一定把内存立刻还给内核”：分配器往往保留块供复用；大块才可能 `munmap`。
- “`MAP_SHARED` 自动解决并发”：它只解决可见性；一致性仍需原子操作、锁或协议。
- “`mprotect` 是软件约定”：页表权限由 MMU 检查，非法访问会陷入内核。
