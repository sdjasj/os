# 第 15 章：系统安全——身份、权限、漏洞与供应链

> 对应讲义：[第 28 讲](../sources/notes/lect28.md)，配套实验：[constant_time_compare.c](../examples/constant_time_compare.c)

安全不是一项可以最后补上的功能，而是“在明确攻击者能力后，系统仍维持哪些性质”。机制若没有威胁模型，只会制造虚假的安全感。

## 15.1 CIA 与威胁模型

- **Confidentiality**：未授权主体不能读取信息。
- **Integrity**：未授权主体不能篡改信息或系统行为。
- **Availability**：授权用户能在约定条件下获得服务。

先写攻击者能做什么：能提交网络输入吗？有普通本地账户吗？能观察时间/功耗吗？能控制依赖仓库或设备吗？能物理接触机器吗？不同模型需要完全不同的防御。

## 15.2 密码学提供原语，不提供系统设计

- 加密保护机密性；
- MAC/数字签名保护完整性与来源；
- cryptographic hash 提供固定长度摘要；
- 随机 nonce、IV 和 key 必须满足算法要求；
- 密码存储要用带盐的专用慢 KDF，而不是普通 hash。

算法正确仍可能因密钥泄漏、随机数失败、重放、错误证书验证或侧信道而失守。不要自行设计密码协议，使用经过审查的高层库，并把密钥生命周期纳入系统设计。

## 15.3 访问控制矩阵

可把策略想成主体对对象拥有的操作集合：

| 主体 \ 对象 | 配置文件 | socket | 摄像头 |
|---|---|---|---|
| web 服务 | read | accept | none |
| 管理员 | read/write | inspect | configure |

UNIX 用 UID/GID、mode、ACL 与 capability 近似实现。内核在打开对象时根据进程凭据和对象元数据检查；得到 fd 后，fd 本身又像一张能力票据。因此把敏感 fd 意外继承给子进程会绕过后续路径权限检查，`O_CLOEXEC` 很重要。

root 的全能身份难以最小化权限。Linux capabilities 把一部分特权拆开，namespace 进一步改变进程看到的身份与对象范围；seccomp 限制可调用的系统调用。它们需要组合，单独使用都不是完整沙箱。

## 15.4 内存破坏如何变成控制流劫持

未检查长度的栈写入可能覆盖相邻数据、返回地址或函数指针。防御层包括：

- 边界安全的语言/库与输入校验：真正消除漏洞；
- stack canary：检测部分返回前栈破坏；
- NX/W^X：阻止直接执行可写数据；
- ASLR/PIE：随机化地址；
- CFI、shadow stack、PAC：约束控制流；
- sandbox：降低成功利用后的权限。

缓解措施提高攻击成本，却不能替代修复越界。信息泄漏可能绕过 ASLR，ROP 可复用已有可执行代码，数据导向攻击甚至不修改控制流。

编译 C 项目可启用合理 hardening，并结合 sanitizer 测试：

```bash
cc -O2 -D_FORTIFY_SOURCE=3 -fstack-protector-strong \
  -fPIE -pie -Wl,-z,relro,-z,now program.c -o program
```

具体选项需按编译器、平台和性能测试调整。

## 15.5 侧信道：输出之外也在泄漏

比较密码若遇到首个不同字节就返回，运行时间与正确前缀长度相关。运行：

```bash
./examples/constant_time_compare secret xxxxxx
./examples/constant_time_compare secret secrxx
./examples/constant_time_compare secret secret
```

示例打印比较次数；常数时间版本始终遍历全部字节：

```c
difference |= left[i] ^ right[i];
```

真实“constant-time”还依赖编译器和硬件，长度本身也可能泄漏，应使用密码库提供的比较函数。缓存、分支预测、页错误、功耗和共享资源都可能成为侧信道；Meltdown/Spectre 更展示了推测执行如何跨越传统抽象边界。

## 15.6 TOCTTOU 与路径攻击

攻击者能在检查和使用之间替换 symlink 或目录项：

```text
check("safe/path") ── attacker swaps link ── open("safe/path")
```

原则是用不可变引用代替重复名字解析：打开目录 fd 后用 `openat` 系列，一次性要求 `O_NOFOLLOW`/`RESOLVE_BENEATH`，再对 fd `fstat`。临时文件使用 `mkstemp` 或 `O_TMPFILE`，不要先猜文件名再创建。

## 15.7 最小权限与隔离

可靠服务启动流程常是：

1. 在高权限阶段只完成必须的端口/设备打开；
2. 设置资源限制，关闭无用 fd；
3. 切换到专用 UID/GID，删除 capabilities；
4. 进入合适 namespace/chroot/rootfs；
5. 安装 seccomp 与 MAC 策略；
6. 解析不可信输入的组件进一步隔离；
7. 记录可审计事件但不泄漏秘密。

隔离层要假设相邻层可能失守。浏览器把网页、渲染器、GPU、网络服务拆进不同进程，就是缩小单个漏洞的影响半径。

## 15.8 Agent 与供应链的新风险

Agent 能读仓库、调用 Shell、访问网络和凭据后，提示注入就可能变成真实权限滥用。应把模型输出视为不可信建议，并实施：

- 工具按最小权限分组，危险动作需单独批准；
- 数据内容与控制指令分离，不让网页文本直接取得工具权；
- 对命令、目标路径和外发数据做结构化校验；
- 凭据短期、可撤销、按任务限定；
- 保存可审计调用记录；
- 在隔离环境执行生成代码。

供应链同样要求验证来源、锁定依赖、审查安装脚本、保护构建与发布凭据、生成 SBOM，并能快速轮换受影响组件。依赖越多，可信计算基越大。

## 15.9 常见误区

- “用了加密所以安全”：身份认证、密钥管理、重放和端点安全仍可能失败。
- 权限检查一次后可永久信任路径：名字解析状态会变化。
- 容器就是强安全边界：容器共享宿主内核，内核漏洞影响面更大。
- ASLR 修复内存错误：它只是概率性缓解。
- 日志越多越安全：秘密、token 和个人数据写入日志会形成新泄漏面。
- 内网输入可信：横向移动、SSRF 和被攻陷服务会把内网变成攻击来源。
