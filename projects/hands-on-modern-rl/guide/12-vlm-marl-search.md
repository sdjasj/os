# 12. 多模态、多个智能体与搜索：辨认训练对象发生了什么

有了多轮轨迹，强化学习还能沿三个方向扩展。VLM 把图像加入状态，多智能体任务让多个策略共同改变环境，推理时搜索则在固定模型之上分配更多计算。三者都会出现“候选—评分—选择”，但训练对象不同。本章用仓库中的轻量代码建立边界，避免仅凭曲线或术语把模拟、搜索和参数训练混在一起。

主线从 [VLM GRPO 模拟](vlm_grpo_train.py) 出发，配合 [几何图形数据生成](geometry_counting_dataset.py) 和 [多模态奖励](multi_modal_reward.py)。随后选读 [多智能体网格世界](../chapter12_future_trends/multi_agent_marl.py) 与 [24 点思维树搜索](../chapter12_future_trends/tree_of_thought.py)。

## VLM 把图像加入了哪一段计算

纯文本模型把提示分词后得到 token 序列。VLM 还要把图像切成 patch，通过视觉编码器和投影层转为视觉 token，再与文本 token 共同送入语言模型：

```text
pixels
  -> image processor
  -> vision encoder
  -> projector
  -> visual tokens ─┐
                    ├-> language model -> response tokens
text -> tokenizer ──┘
```

强化学习的动作仍可定义为生成的文本 token，状态中却多了图像和跨模态上下文。训练时要明确哪些参数更新：

- 只更新语言模型：成本较低，视觉表征固定；
- 更新投影层：模型可以调整视觉信息如何进入语言空间；
- 联合更新视觉编码器：表达能力更强，显存与稳定性成本显著提高；
- 使用 LoRA 等适配器：减少可训练参数，但不会消除 rollout 和激活内存。

## 用几何计数任务拆解数据契约

[数据生成脚本](geometry_counting_dataset.py) 用 Pillow 绘制三角形、圆形和正方形，并保存对应数量。一个真实训练样本至少需要：

```python
sample = {
    "image_path": "...",
    "prompt": "请数一下图片中的三种图形",
    "ground_truth": {"三角形": 2, "圆形": 3, "正方形": 1},
}
```

这里有三条必须保持的不变量：

1. `ground_truth` 必须来自绘图过程，而不是从模型回复反推；
2. 训练、验证、测试的图像随机种子或模板要分开；
3. 模型输入不能包含会直接泄漏计数结果的文件名、metadata 或 alt text。

运行数据生成器：

```bash
cd <project-root>/code
python -m pip install -r chapter11_vlm_rl/requirements.txt
python chapter11_vlm_rl/geometry_counting_dataset.py
```

先人工抽查图像与标签。合成管线若生成了重叠、越界或难以辨认的图形，奖励函数再精确也只是在优化错误标签。

## 多模态奖励依然要分解

[多模态奖励脚本](multi_modal_reward.py) 将最终得分拆成正确性、推理质量、格式和视觉定位。分解的价值在于定位错误：

| 分量 | 想衡量的能力 | 可能的捷径 |
| --- | --- | --- |
| 正确性 | 图形数量是否匹配 | 从泄漏的 metadata 猜答案 |
| 推理质量 | 是否给出可理解过程 | 堆叠连接词和固定句式 |
| 格式 | 是否包含规定字段 | 格式正确但内容错误 |
| 视觉定位 | 是否引用图像中的对象 | 复述提示中的形状名称 |

脚本的奖励函数接收文本回复、标准答案和 `image_info`，没有从像素重新验证模型是否真正看到了对象。因此“视觉定位奖励”是基于文本和元信息的启发式代理。它适合演示奖励接口，不能单独证明视觉 grounding。

更可靠的评估需要保留独立测试集，并设计无法仅由文本先验回答的图像。例如固定提示、随机计数、随机位置和诱导性干扰图形；同时对图像打乱、遮挡和空白输入做对照。

## 先读清 VLM GRPO 模拟中的数据流

`create_training_samples` 只随机生成计数字典：

```python
gt = {
    "三角形": random.randint(0, 5),
    "圆形": random.randint(0, 5),
    "正方形": random.randint(0, 5),
}
```

它没有载入前一脚本生成的图片。`simulate_grpo_training` 再按 `quality_factor` 从预设文本模板中选择回答：

```python
quality_factor = initial_quality + (
    1.0 - initial_quality
) * (epoch / max(num_epochs - 1, 1))
```

随着 epoch 增长，生成正确模板的概率被代码直接调高。因此输出的准确率和奖励曲线上升是模拟设定的结果，没有任何模型参数、视觉编码器或优化器参与更新。

本脚本准确的定位是“多模态奖励与组内归一化的数据流演示”。它可以回答：一个问题采样多条回答后如何评分、如何计算组内优势、应该记录哪些统计量。它不能回答：VLM 是否从像素学会计数。

### 运行模拟并验证因果关系

```bash
cd <project-root>/code
python chapter11_vlm_rl/vlm_grpo_train.py
```

先运行默认版本，再把 `quality_factor` 固定为 `initial_quality`。若后者曲线不再系统上升，就验证了默认上升来自模拟调度，而非训练。随后改变 `group_size`，观察奖励标准差为零的组出现频率。

## 真实 VLM GRPO 需要补上的闭环

一个实际参数更新循环至少包含：

```text
(image, prompt)
  -> 当前策略采样 G 个响应并保存旧 token log-prob
  -> verifier 对每个响应评分
  -> 同题组内计算优势
  -> 当前策略重算可训练 token log-prob
  -> PPO/GRPO clipped objective + reference KL
  -> optimizer.step()
  -> 独立验证集评估
```

与当前模拟相比，缺失项包括：

- 实际图像 processor 和视觉 token；
- 可训练 VLM 与参考模型；
- 旧策略对数概率、动作掩码和裁剪目标；
- 优化器更新和梯度检查；
- 独立验证集与真实视觉对照。

仓库注释提到完整训练可能需要高显存 GPU。具体需求取决于模型、分辨率、组大小、序列长度、精度、是否冻结视觉编码器和分布式切分方式；不要把示例中的单一显存数字当作通用最低要求。

## 多智能体任务改变了环境的稳定性

单智能体 Q-learning 假设环境转移规律在学习期间相对稳定。多个智能体同时更新策略时，从任一智能体视角看，其他智能体的行为分布不断变化，于是环境呈现非平稳性。

[多智能体网格世界](../chapter12_future_trends/multi_agent_marl.py) 中有 3 个智能体、资源点、墙和协作奖励。每一步接收联合动作：

```python
next_obs, rewards, done, info = env.step(actions)
```

联合动作空间随智能体数指数增长。若每个智能体有 \(|A|\) 个动作，\(N\) 个智能体的联合动作数是 \(|A|^N\)。独立 Q-learning 避免显式建立联合表，但把其他学习者的变化当作环境噪声。

### 观测缺少什么

`_get_observations` 只返回每个智能体的位置。Q 表键再加上剩余资源数量：

```python
return (row, col, resources_left)
```

它没有包含资源位置、墙的相对关系或其他智能体的位置。两个完全不同的世界可能映射到同一个键，所以这是部分可观测状态。若表现停滞，先检查状态是否足以决策，再调整学习率。

### “共享策略”是否真的共享经验

`SharedPolicyAgent` 使用同一个字典，但键为：

```python
return (agent_id, row, col, resources_left)
```

`agent_id` 使不同智能体访问互不重叠的键。它们共享容器和更新代码，却很少共享相同状态动作参数，因此不能仅凭名称断言样本效率一定提高。

一个直接的消融实验是移除 `agent_id`，前提是智能体角色对称；再比较训练速度和最终行为。若起点或职责不同，还可加入角色嵌入而不是完全分离键空间。

### 运行与记录

```bash
cd <project-root>/code
python chapter12_future_trends/multi_agent_marl.py
```

除了团队总奖励，还应记录：

- 每个智能体的回报分布；
- 完成率和完成步数；
- 资源分配是否长期偏向某个智能体；
- 协作奖励占总奖励的比例；
- 同一配置的多随机种子区间。

团队奖励上升可能伴随个别智能体长期得不到资源。公平性和协作质量不能由总和指标替代。

## 思维树是搜索，不是参数训练

[24 点思维树脚本](../chapter12_future_trends/tree_of_thought.py) 把一个局面表示为 `ThoughtNode`，生成所有合法算术子节点，用启发式函数评分，然后每层保留前 `breadth` 个：

```text
current beam
  -> generate all children
  -> evaluate each child
  -> sort by score
  -> keep top-k
  -> expand next level
```

`breadth=1` 退化为贪心单链；更大的束宽保留更多候选，计算成本也随之增加。这个过程在推理时选择路径，没有优化模型参数，没有策略梯度，也没有从交互数据更新价值函数。

搜索与 RL 可以组合：训练模型提出候选、训练价值模型评分节点、用搜索结果产生偏好数据。但当前脚本使用手写算术转移和启发式评分，应称为束搜索演示。

### 一个公平的搜索对比

比较单链、思维树和随机搜索时要统一预算。可以固定“总评估节点数”，而不只固定每种方法的循环次数。报告：

- 精确解成功率；
- 每题评估节点数；
- 首次找到解的时间；
- 未找到时与目标的误差；
- 不同题目难度和随机种子。

如果思维树评估了数百个节点而单链只评估 3 个，把成功率差异全部归因于“推理方法”并不公平，其中包含额外计算预算的贡献。

## 三种扩展的统一对照

| 方向 | 新增对象 | 被优化的参数 | 主要难点 |
| --- | --- | --- | --- |
| VLM RL | 图像、视觉 token、多模态奖励 | VLM 策略参数 | 显存、视觉捷径、奖励验证 |
| 多智能体 RL | 联合动作、其他学习者 | 一个或多个策略 | 非平稳、信用分配、协作公平 |
| 推理时搜索 | 候选树和评估预算 | 当前脚本无参数更新 | 分支爆炸、评分误差、预算公平 |

看到一个新项目时，先问“本轮究竟更新了哪些参数”。若答案是没有参数更新，它可能是评估、数据生成或搜索组件；这些组件仍然重要，但不能用训练术语掩盖其真实作用。

## 动手实验：检查视觉捷径

为几何计数数据设计四组评估：

1. 正常图像与正常提示；
2. 打乱图像但保留标签；
3. 空白图像与正常提示；
4. 正常图像但删除任何可能泄漏标签的 metadata。

真实 VLM 若在 2、3 组仍保持高准确率，应检查数据泄漏或文本先验。奖励函数也要在错误但格式完整、正确但简短、复述形状名称却未计数等反例上测试。

## 动手实验：把模拟改成可证伪实验

保留当前响应模板，不增加模型训练，做以下修改：

- 删除随 epoch 自动增长的 `quality_factor`；
- 固定每个样本的候选响应集合；
- 只改变奖励权重和组大小；
- 报告候选排序、零方差组比例与奖励各分量。

这样曲线不再伪装成学习过程，实验可以清楚回答“奖励规则怎样选择已有候选”。之后再接入真实 VLM 时，新增的 optimizer 更新才是独立变量。

## 本章小结

VLM RL 改变输入和模型结构，多智能体 RL 改变环境的稳定性与联合信用，推理时搜索改变每个问题可用的计算预算。仓库为三者提供了有用的机制代码，也保留了明显的教学简化：VLM 脚本没有图像和参数更新，多智能体状态缺少关键信息，“共享”Q 表的键仍按智能体分离，思维树只做搜索。准确命名实验对象，是进入下一章调试与综合实践的第一步。
