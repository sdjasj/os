# 13. 训练诊断与综合项目：把“曲线变好”变成可检验结论

强化学习训练同时改变策略、数据分布和学习目标。
一次运行奖励上升，只能说明这条随机轨迹上的某个记录量发生了变化；它还不能证明算法稳定、奖励与任务一致，也不能证明换一个随机种子仍然成立。
本章把前面学到的环境、价值、策略、奖励和评估放进一套可执行诊断顺序，最后用三个综合项目完成验收。

本章的源码链接以[训练崩溃脚本](debug_training_collapse.py)所在的 `code/appendix_common_pitfalls/` 为语境。

## 先理解两个教学脚本

[训练崩溃脚本](debug_training_collapse.py)构造四个 DQN 配置：高学习率、无梯度裁剪、探索率不衰减和参考配置。
它记录回合奖励、损失、梯度范数和左右动作次数，用来展示“同一训练循环只改一个开关”的实验形式。

[奖励错位脚本](debug_reward_hacking.py)保持 DQN 主体不变，通过 Gymnasium wrapper 修改奖励，并同时记录训练奖励与原始任务得分。
它展示了一个关键接口：环境可以返回用于学习的奖励，评估器则应另外计算真实目标。

从上游仓库的 `code/` 目录运行：

```bash
python -m pip install -r appendix_common_pitfalls/requirements.txt
MPLBACKEND=Agg python appendix_common_pitfalls/debug_training_collapse.py
MPLBACKEND=Agg python appendix_common_pitfalls/debug_reward_hacking.py
```

两个脚本都会运行多个 300 回合场景，适合在理解代码后执行，不适合作为秒级冒烟测试。
图像分别写入 `output/training_collapse_diagnosis.png` 和 `output/reward_hacking_diagnosis.png`。

## 第零步准备与七步诊断

诊断顺序的目的，是让每一步只排除一类原因。
先改优化器再检查环境，可能会用调参掩盖状态、奖励或终止语义错误。

### 第零步：冻结实验语境

开始复现前先保存：

- 源码提交、工作目录和完整命令；
- Python、PyTorch、Gymnasium 与关键依赖版本；
- 环境 ID、wrapper 顺序和时间上限；
- 训练步数、更新次数、batch size 与目标网络频率；
- Python、NumPy、PyTorch、环境和评估的种子；
- 设备、精度和运行时间；
- 训练奖励与独立任务指标的定义。

无法回答这些问题时，不要比较两条曲线。

### 第一步：验证环境和轨迹语义

先随机运行几个短 episode，逐步检查：

1. 观测形状和数值范围是否符合环境定义；
2. 动作是否属于动作空间；
3. 奖励是否有限，量级是否符合设计；
4. `next_state` 是否在重置前保存；
5. episode 是否在 `terminated or truncated` 时停止；
6. 价值 bootstrap 是否只在真正终止时清零。

推荐把“需要重置”和“价值是否终止”写成两个变量：

```python
episode_done = bool(terminated or truncated)
terminal_for_value = bool(terminated)

replay.push(state, action, reward, next_state, terminal_for_value)
if episode_done:
    state, info = env.reset()
else:
    state = next_state
```

固定快照的两个附录脚本存入 replay 的是 `done`，没有把 `truncated` 的语义明确保留下来。
在带时间上限的环境里，这会影响 TD 目标，应在解释实验前先核对。

### 第二步：建立最小基线

基线回答“环境和评估协议是否有辨别力”。
至少运行：

- 随机策略；
- 一个固定动作策略；
- 未训练网络的确定性策略；
- 仓库提供的参考超参数。

若随机策略和训练策略得到相近的独立评估，先检查评估与奖励，不要直接增加训练时间。
若所有策略都满分，任务或评估可能太容易；若所有策略都零分，奖励可能过稀疏或环境有误。

### 第三步：检查数值健康

每次更新至少监控：

- 损失及其有限性；
- 梯度全局范数；
- 参数范数与参数更新范数；
- Q 值或状态价值的均值、标准差和极值；
- TD 目标与 TD 误差；
- batch 中奖励和终止比例。

发现第一个 NaN 后应立即保存前一个正常 batch，并停止扩散。
继续用零替代 NaN 只适合画教学图，不能作为真实训练的恢复方案。

### 第四步：检查数据和策略分布

DQN 要检查探索率、replay 大小、状态覆盖和动作条件分布；策略梯度要检查熵、对数概率、优势均值和优势尺度；PPO 还要检查 KL 与裁剪比例。

聚合动作次数只能回答“总体选了多少次”，不能回答“在同一状态附近是否总选一个动作”。
更有效的检查是按杆角度或状态簇分箱，再统计条件动作概率：

```text
angle bin       P(left)   P(right)   samples
[-0.20,-0.05)      ...       ...       ...
[-0.05, 0.05)      ...       ...       ...
[ 0.05, 0.20]      ...       ...       ...
```

动作分布偏斜可能是正确控制策略，也可能是退化；必须与状态、回报和轨迹一起解释。

### 第五步：分离训练与评估

训练环境用于收集带探索的数据，评估环境只衡量当前策略。
评估时应：

- 使用独立环境实例；
- 禁止梯度和参数更新；
- 固定一组未用于挑选结果的评估种子；
- 对随机策略报告多次采样，对确定性策略固定决策规则；
- 记录均值、标准差、每个种子的原始值和失败率；
- 用相同环境步预算比较算法。

按 episode 数比较可能不公平，因为高回报策略的 episode 更长，会获得更多环境步和更新机会。

### 第六步：分离训练奖励与任务指标

训练奖励是优化器看到的信号；任务指标是人真正关心的结果。
两者可以相关，但不能用同一公式重复命名。

CartPole 可同时记录：

- 修改后的训练奖励；
- episode 长度；
- 成功达到时间上限的比例；
- 平均绝对杆角度；
- 平均绝对小车位置；
- 多初始状态评估回报。

语言或 Agent 任务可把格式正确率、最终答案正确率、工具调用有效率、引用支持率和任务成功率分开。
总奖励上升后，逐项指标能指出模型究竟学到了什么。

### 第七步：一次只做一个消融

建立稳定基线后，才改变学习率、梯度裁剪、探索衰减或奖励项。
保持种子集合、步预算、评估协议和其余参数相同。

如果移除一个组件后表现变差，还要排除“该配置只适合原组件”的可能。
至少补一个邻近超参数点，再判断组件作用。

## 指标矩阵：每个量能证明什么

| 指标 | 能发现的信号 | 单独不能证明什么 | 下一项证据 |
| --- | --- | --- | --- |
| 训练回合奖励 | 当前行为数据上的奖励趋势 | 泛化、稳定性、真实目标 | 独立评估与任务指标 |
| 独立评估回报 | 固定协议下的策略表现 | 奖励是否符合人类目标 | 任务专属指标与反例 |
| 成功率 | 是否跨过任务门槛 | 成功路径质量 | 长度、代价与行为审查 |
| 损失 | 当前 batch 的拟合误差 | 策略是否进步 | 评估回报、值尺度 |
| 梯度范数 | 更新信号是否异常放大 | 参数是否真的移动合理 | 更新范数、学习率 |
| Q 值或 V 值 | 价值尺度与漂移 | 估计是否校准 | TD 目标与实际回报 |
| TD 误差 | 一步目标不一致程度 | 长期策略质量 | 多步回报与评估 |
| 动作比例 | 总体动作使用情况 | 状态条件下的策略退化 | 条件动作分布、熵 |
| 探索率或熵 | 随机性是否变化 | 探索是否有效 | 状态覆盖和新颖样本 |
| KL / 裁剪比例 | PPO 更新是否受限 | 限制后的方向是否正确 | 奖励、任务指标 |
| reward 分项 | 优化压力来自哪里 | 组合奖励是否无漏洞 | 对抗样本和任务评估 |

任何固定阈值都依赖网络、奖励尺度和记录方式。
附录脚本中“梯度大于 100 或 1000”的判断是教学启发式，不能直接迁移到别的任务。

## 多随机种子：报告完整分布

强化学习方差来自初始化、探索、环境转移和 batch 顺序。
课程规模实验至少使用 5 个训练种子，并为每个模型使用同一组评估种子。

一个最小汇总函数如下：

```python
import numpy as np

def summarize(seed_scores):
    values = np.asarray(seed_scores, dtype=np.float64)
    return {
        "values": values.tolist(),
        "mean": float(values.mean()),
        "std": float(values.std(ddof=1)),
        "min": float(values.min()),
        "max": float(values.max()),
    }
```

样本很少时，不要用过多小数制造精确感。
图上同时画每个种子的点和总体区间；失败种子不能静默删除。

## 对固定快照教学脚本的必要校正

### 奖励错位示例并未完整证明奖励作弊

`HackedRewardWrapper` 的场景 1 在每个存活步给原始 `1` 分再加固定 `2` 分，而脚本的任务得分也是每步累加 `1`。
对任意 episode 都有：

\[
R_{train}=3\times \text{steps},\qquad M_{task}=\text{steps}.
\]

两者严格单调等价，因此这个场景本身不能产生“训练奖励上升而任务指标下降”的证据。
它可以用于练习双指标记录，却不能单独作为奖励破解案例。

位置塑形场景更可能改变行为，但仍需把杆角度、位置、成功率和跨初始状态表现作为外部指标。
仅靠相关系数也不够：相关可能来自共同依赖 episode 长度，低相关也可能只是采样噪声。

### “无裁剪”与“动作不均”都不是充分条件

关闭梯度裁剪不会保证 CartPole DQN 必然爆炸。
正常学习率、目标网络和 Adam 可能让这次运行保持有限；裁剪是风险控制，是否必要要由多种子消融决定。

总体动作比例超过某个阈值也不能单独证明策略退化。
控制任务的正确动作依赖状态；必须查看条件动作分布、轨迹和回报。

### 其他限制

- 脚本没有为每个场景建立完整且一致的随机种子协议；
- 高学习率是否出现 NaN 具有随机性，不应把一次未复现解释为代码失效；
- NaN 被替换成零后，后续曲线只便于展示，不再代表有效训练；
- `done` 与 `truncated` 没有完整进入 replay 语义；
- 每回合平均损失和梯度会受 episode 长度影响；
- 固定动作阈值和梯度阈值只适用于这个教学配置。

这些限制不会抹去脚本的教学价值。
它们恰好说明：诊断工具本身也需要独立验证。

## 综合项目一：CPU 经典 RL 对照实验

### 任务

从[DQN CartPole](../chapter04_dqn/dqn_cartpole.py)、[REINFORCE 与基线](../chapter05_policy_gradient/reinforce_with_baseline.py)和[Actor-Critic](../chapter05_policy_gradient/actor_critic_cartpole.py)中选择两种方法，在相同 CartPole 环境步预算下比较。

### 实施

1. 固定 5 个训练种子和 20 个评估种子；
2. 将预算统一为环境步，并单独记录 episode 数；
3. 每隔固定步数做独立确定性评估；
4. 记录回报、成功率、梯度范数或价值尺度；
5. 只做一个消融，例如 REINFORCE 是否使用价值基线；
6. 保存逐种子 CSV、配置和汇总图。

### 验收标准

- 一条命令能够重新运行每个配置；
- 环境正确区分 `terminated` 与 `truncated`；
- 报告全部种子，不筛掉失败运行；
- 图中同时显示个体运行和均值波动；
- 训练与评估环境分离；
- 结论说明证据支持和不支持的范围，即使两算法差异不显著也算有效结果。

## 综合项目二：规则奖励的单元测试与压力测试

### 任务

以[规则奖励脚本](../chapter09_grpo_rlvr/rule_based_reward.py)和[GRPO 机制脚本](../chapter09_grpo_rlvr/grpo_mechanism.py)为起点，为数学回答建立离线 verifier 测试集。

### 实施

测试集至少覆盖：正确且格式正确、正确但格式异常、错误但格式漂亮、缺少最终答案、多个冲突答案、等价数值表示和无关文本。
把答案正确性、格式与其他分项分别输出，不要只保留加权总分。
再检查一组奖励全部相同、标准差接近零以及仅一个离群值时，组内优势是否有限且符合预期。

### 验收标准

- 至少 30 个手写且分层标注的测试例；
- 每个奖励分项都有确定性断言；
- 报告错误接受和错误拒绝案例；
- 总奖励权重集中写入配置；
- 全等组不会产生 NaN 或无穷大；
- 不下载模型、不调用外部 API 也能完成全部验收。

## 综合项目三：离线工具调用 Agent

### 任务

使用[工具选择策略](../chapter10_agentic_rl/tool_use_agent.py)或[离线 Deep Research 基准](../../docs/chapter22_agentic/code/deep_research_rl_benchmark.py)，构建只访问固定内存语料的 Agent。
不要使用任意代码执行，也不要调用网络服务。

### 实施

把任务分成训练集和未见测试集；轨迹只记录问题、工具名、结构化参数、观测、最终答案和奖励分项。
先运行随机工具基线，再训练策略。
对无效工具、空查询、错误文档和正确答案分别给出可解释的奖励。

### 验收标准

- 默认运行无网络、无 API 密钥、无任意代码执行；
- 固定语料、任务划分、种子和最大轮数；
- 每条轨迹可序列化并通过 schema 检查；
- 报告随机基线、训练集和未见测试集成功率；
- 分开报告工具有效率、证据选择率和答案正确率；
- 至少包含无效调用、无匹配文档和奖励相同三个失败测试；
- 结论不使用训练任务表现替代泛化结果。
