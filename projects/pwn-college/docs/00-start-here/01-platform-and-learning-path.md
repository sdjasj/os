# 01 · 平台结构与学习方法

> 对应官方模块：[Using the Dojo](https://pwn.college/welcome/welcome/)

## 学习目标

- 区分 dojo、module、challenge 三个层级。
- 用依赖关系而不是“题目数量”安排学习。
- 即使不运行挑战，也能通过静态推演建立可检验的理解。

## 课程为何分层

dojo 是一条大的能力路线，例如 Linux 命令行；module 聚焦一个知识簇，例如管道；challenge 则用一个可观察结果检验某个细节。三者分别回答“学哪一门”“这一章讲什么”“我是否真的会用”。只看结论容易产生熟悉感，却不一定能预测程序行为；挑战的价值正是让预测接受现实检验。

没有时间做完整实验时，可以保留这种检验思想。阅读每个例子前先遮住输出，写下自己的预测，再比较教程给出的结果。如果不同，定位是输入、初始状态、转换规则还是输出解释出了偏差。

```text
输入 ──> 程序读取 ──> 内部状态变化 ──> 输出/副作用
             ↑               │
             └──── 约束条件 ─┘
```

## 安全学习为何强调“反例”

要证明系统在所有输入、状态和时序下都安全，通常需要覆盖巨大的状态空间；要证明某个安全声明不成立，只需找到一个可复现反例。例如“所有未认证请求都无法读取私有记录”是全称命题，只要存在一个未认证读取路径，声明就被推翻。

安全分析的基本循环：

~~~text
写出安全声明
 -> 明确攻击者能力
 -> 枚举输入/状态/边界
 -> 寻找反例
 -> 最小化并解释反例
 -> 修复根因
 -> 用回归测试防止再次出现
~~~

这也是 challenge 的教学意义：它不代表真实世界只有这一种漏洞，而是用一个小环境迫使你给出可验证的反例。没有时间操作时，也应在纸面上明确“安全声明是什么、哪条输入会否定它、修复后为何不再成立”。

## Challenge 的生命周期

平台的一般工作流可抽象为：

1. 在 dojo 中选择 module，再选择 challenge；
2. 启动 challenge，平台创建相应隔离环境；
3. 通过 Terminal、VS Code、GUI Desktop 或 SSH 与环境交互；
4. 阅读 challenge 说明并运行教学程序；
5. 成功满足目标后取得一段 flag token；
6. 把 token 提交给平台，平台记录完成状态；
7. 必要时重启 challenge，清除本次运行状态并重新开始。

具体按钮和界面会变化，应以[官方 Using the Dojo 页面](https://pwn.college/welcome/welcome/)为准。教程不会展示任何真实 flag 格式或当前挑战输入。

### Challenge 程序与 flag 文件

教学环境常把本关程序放在 <code>/challenge</code> 之类的明确位置，把受保护目标表示为 flag 文件或由服务返回的 token。关键模型是：

~~~text
你的普通进程权限
  -> 与 challenge 程序交互
  -> 程序在预设条件下获得/返回目标
  -> 平台验证提交 token
~~~

直接知道“flag 在哪里”不等于有读取权限。课程要训练的是理解程序和权限边界，使目标通过设计好的学习路径变得可达，而不是猜 token。

## 四种工作入口怎样选择

| 入口 | 适合任务 | 主要特点 |
|---|---|---|
| Terminal | 命令、管道、编译、GDB | 最直接，后续教程默认入口 |
| VS Code Workspace | 多文件阅读与编辑 | 终端和编辑器结合，适合较长程序 |
| GUI Desktop | 浏览器、图形调试器、需要桌面的程序 | 远程桌面会有剪贴板和键位差异 |
| SSH | 本地终端、个人配置和稳定复制 | 需先把自己的公钥关联到账户 |

同一 challenge 的后端环境可以由不同前端观察，但终端尺寸、环境变量、剪贴板和网络连接可能略有差异。遇到“只在某入口失败”时，先比较这些环境因素。

### Terminal

提示符等待 shell 命令。不要把教程代码块里的美元提示符或输出行一起粘贴为命令。执行前先确认当前目录、用户和目标路径：

~~~bash
pwd
id
printf 'shell=%s\n' "$SHELL"
~~~

### VS Code Workspace

编辑器适合保存脚本、查看差异和使用集成终端。要区分：

- 文件是否真的保存；
- 当前打开的是宿主文件还是 challenge 环境文件；
- 集成终端当前目录；
- 扩展是否可信；
- 运行按钮使用的解释器和参数。

“编辑器里看到新内容”但程序仍运行旧文件，常因未保存或执行路径不同。

### GUI Desktop 与粘贴

远程桌面的剪贴板桥接可能要求专门的粘贴动作；浏览器快捷键也可能先被本地系统截获。粘贴前先在无害文本框/终端用短字符串确认边界，尤其注意多行命令会立即逐行执行。

不要一次粘贴来源不明的长命令。先放入编辑器阅读，理解重定向、删除、下载和权限操作，再逐段运行。

### SSH

SSH 使用密钥时，本地保留私钥，只把公钥添加到平台设置。检查连接目标主机名和主机密钥提示，不要把私钥、agent socket 或其他环境凭据复制进 challenge。

SSH 连接断开不等于挑战程序一定停止；前台进程可能收到挂断信号，tmux/screen 内的进程通常继续。需要持久任务时使用明确的作业管理，并在结束后清理。

## 重启与持久化目录

重启 challenge 常用于恢复初始进程和题目状态，但 HOME 中的个人文件可能按平台设计在 challenge 之间持久保存。于是要区分：

~~~text
题目运行状态：可能随重启重建
个人 HOME：可能跨重启/跨题持久
平台完成记录：保存在账户侧
~~~

不要把“重启”当作删除自己保存的脚本、历史或敏感数据。建议：

- 每个 module 使用独立子目录；
- 文件名记录用途，不记录真实秘密；
- 重新开始前检查 HOME 中旧脚本是否改变 PATH/环境；
- 不在持久目录保存课程 flag、第三方凭据或私钥；
- 重要学习笔记另行备份。

### Privileged mode

平台可能提供 privileged 实践模式，让学习者在同类环境中以更高权限观察系统。它适合回答“若拥有管理员权限，内部状态是什么”，但通常不代表完成 challenge，也不应成为绕过学习目标的捷径。

高权限模式会放大误操作：先确认环境标签和目标路径，不运行破坏性命令，不把它与工作机上的 root shell 混淆。

## 一个最小推演例子

下面的命令不是任何挑战答案，只用于展示“数据经过两次转换”的读法：

```bash
printf '%s\n' 'pear' 'apple' 'pear' | sort | uniq -c
```

预期输出：

```text
      1 apple
      2 pear
```

推演过程：`printf` 产生三行输入；`sort` 把相同值排到一起；`uniq -c` 只统计相邻重复行。因此，若去掉 `sort`，两个 `pear` 不再相邻，计数结果就会改变。这里重要的不是记住命令，而是能说清每一步的前置条件。

## 建议的阅读循环

1. 先读目标，回忆先修概念。
2. 在看输出前预测命令结果。
3. 沿数据流逐步解释每个字符、参数和返回值。
4. 主动改变一个条件，例如空输入、重复值或无权限文件。
5. 用自己的话写下“不变量”：哪些条件改变后，结论仍成立。

后续安全主题尤其依赖这种习惯。漏洞往往不是某条“神奇命令”，而是开发者以为某个不变量成立，攻击者却找到了破坏它的输入或时序。

## 常见误区

- **把读懂等同于会做。** 能复述定义不代表能预测边界情况；至少完成纸面推演。
- **跳过基础直接背利用模板。** 模板依赖架构、内存布局、权限和输入通道，条件一变就失效。
- **只记成功路径。** 错误输出、退出码和权限失败同样是系统行为的一部分。
- **追求章节数量。** 稳固的依赖链比快速扫完更多 module 更有价值。

## 纸面练习

不运行命令，判断下面管道的输出：

```bash
printf '%s\n' beta alpha beta | sort -u | wc -l
```

### 答案

输出为 `2`。`sort -u` 排序并去重，只保留 `alpha`、`beta` 两行；`wc -l` 统计两行。若误答 `3`，通常是忽略了 `-u`；若认为输出具体单词，则是忽略了最后一次转换。

## 小结

学习路径的核心不是收集答案，而是建立可预测、可解释、可迁移的模型。把每个示例拆成输入、状态、转换和输出，即使暂时不操作平台，也能获得比机械浏览更可靠的理解。
