# 02 · 伦理边界与安全环境

> 相关官方入口：[Start Here](https://pwn.college/welcome/)；交流渠道见 [Joining the Discord](https://pwn.college/welcome/discord/)

## 学习目标

- 用“明确授权”判断一项安全操作能否进行。
- 理解隔离、最小权限和可恢复性为何是实验环境的三条底线。
- 使用本地临时目录安全地运行教程命令。

## 授权比技术能力更先行

同一个扫描、调试或输入构造动作，在自己的练习程序上是学习，在未授权服务上可能造成损害并违反法律或合同。判断时不要依赖“我只是看看”这种主观意图，而要确认对象、方法、时间范围和允许的影响均有明确授权。

一个实用检查表是：

1. **对象是谁的？** 自有设备、本地练习镜像或明确列入范围的靶场。
2. **允许做什么？** 阅读公开页面不等于允许发送攻击载荷。
3. **影响能否控制？** 避免真实数据、第三方流量和资源耗尽。
4. **失败能否恢复？** 使用快照、临时目录和可重建数据。

## 最小权限与隔离

普通用户权限能限制误操作的影响；独立临时目录把文件范围变得清晰；只监听 `127.0.0.1` 的示例服务不会主动暴露到外网。容器和虚拟机能增强隔离，但不是免责工具：错误的目录挂载、特权模式或端口映射仍可能影响宿主机。

## 加入 Discord：把社区当作学习协作，而不是答案仓库

pwn.college 的 Start Here 路径包含 Joining the Discord。若要把站内身份与 Discord 关联，应从登录后的 [pwn.college 设置页](https://pwn.college/settings#discord)进入绑定流程，而不是把密码、会话 cookie、token 或 flag 发给任何人。授权页面应核对域名；来历不明的机器人、私信链接和可执行附件都应按不可信输入处理。

社区最有价值的用途是帮助你校准思路：确认自己对概念的理解、寻找公开文档、描述已排除的假设，以及得到不会代替学习过程的提示。一个容易获得有效帮助的问题通常包含：

1. 正在学习的**公开模块主题**，不要粘贴未公开题面或评分材料；
2. 自己预期的行为与实际观察到的现象；
3. 已尝试的诊断步骤、工具版本和最小错误输出；
4. 已删去用户名、学号、主机名、token、cookie、flag、地址等敏感信息的最小复现；
5. 一个具体问题，例如“这段输出为什么说明发生了短读”，而不是“直接给答案”。

例如，下面的问题暴露了足够的技术上下文，却没有索要关卡解法：

```text
我在自建的本地 C 复制程序中调用 read(fd, buf, 8)，第一次只返回 3。
我原以为阻塞 fd 会填满请求长度。POSIX/Linux 对返回长度实际保证什么？
我已确认 errno 没有被设置，并把最小代码缩减到 20 行。
```

公开频道中不要发布当前挑战的 flag、精确 payload、偏移、solver 或从输入到通关的完整步骤；正式课程学生还要服从所在课程更严格的学术诚信政策。收到私信中的“答案”也不等于可以提交或传播。若日志里含秘密，可用 `<REDACTED>` 替换并保留字段类型和长度；不要只涂截图表面，因为剪贴板、终端滚屏和图片元数据也可能保留信息。

交流时把安全边界说清楚：“对象是我自己编译的程序”“服务只在 `127.0.0.1`”“我只需要理解 ABI”。如果问题涉及未知外部目标、绕过访问控制或破坏性命令，社区也无法替你提供授权。遇到骚扰、可疑文件或索要凭据，应停止交互并使用平台/Discord 的举报与封禁机制。

## 安全的本地工作目录

下面只创建并删除由 `mktemp` 返回的专用目录。变量名加引号，防止路径中的空格被拆分：

```bash
lab_dir=$(mktemp -d)
printf 'training data\n' > "$lab_dir/note.txt"
printf 'workspace=%s\n' "$lab_dir"
ls -l "$lab_dir"
```

预期输出形态如下，随机后缀和时间会不同：

```text
workspace=/tmp/tmp.A1b2C3d4
total 4
-rw-r--r-- 1 user user 14 ... note.txt
```

确认目标后再清理：

```bash
test -n "$lab_dir" && test -d "$lab_dir" && rm -r -- "$lab_dir"
```

这里的两次 `test` 是防御性检查，`--` 告诉 `rm` 后续内容都是路径而非选项。教程不会建议对宽泛目录、未展开变量或未知通配符执行递归删除。

## 示例的安全分级

- 文本处理、编码转换：使用教程内生成的虚构数据。
- 网络示例：仅连接本机回环地址，并使用非特权高端口。
- C、汇编和调试：编译自行给出的微型程序，不接触系统服务。
- 漏洞原理：展示最小根因和修复，不给真实目标利用流程。
- 权限示例：使用当前普通用户拥有的临时文件，不要求 `sudo`。

## 常见误区

- **“公开可访问”就是授权。** 可访问性和测试许可是两回事。
- **容器绝对安全。** 特权容器或危险挂载会削弱边界。
- **命令短所以风险小。** `rm`、权限修改和进程信号的影响取决于目标，不取决于字符数。
- **照抄时省略引号。** 未加引号的变量可能发生分词和通配符展开。

## 纸面练习

有人提供命令 `rm -r $target/*`，但没有说明 `$target` 如何赋值。指出至少两个风险，并给出原则上的改进。

### 答案

第一，变量为空时目标可能意外变成 `/*`；第二，未加引号会触发分词和通配符展开；第三，目标范围未经确认。应使用由程序刚创建、路径明确的专用临时目录，对变量执行非空与目录检查，将路径写成 `"$target"`，并避免拼接宽泛的 `/*`。本教程实际清理时还会展示待删除对象。

## 小结

安全学习的前提是明确授权；安全环境的核心是隔离、最小权限和可恢复。后续所有示例都遵守这一边界，并用可审计的本地对象解释原理。
