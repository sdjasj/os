# 07 · 安全与系统术语表

## 使用方法

术语只有放进关系中才有意义。例如“进程通过文件描述符发起系统调用，内核依据有效 UID 和文件权限决定结果”把进程、fd、syscall、UID 与权限连接成一条因果链。本表重点解释容易混淆的概念及边界，而不是给一句循环定义。

## 数据与表示

### bit（比特）

二进制信息单位，值为 0 或 1。比特是抽象值，不等同于屏幕字符 `'0'` 或 `'1'`；后者各自需要一种文本编码。

### byte（字节）

现代通用系统中通常为 8 bit，是内存寻址和文件大小的基本单位。一个字节可表示 0–255 的无符号整数，但其真实语义取决于上下文。

### word（机器字）

处理器自然处理的一种数据宽度，含义依架构和工具而变。x86 文档中 `word` 还常特指 16 bit，因此不要仅凭“64 位机器”猜测每处 word 都是 64 bit。

### encoding（编码）

把抽象对象映射为符号或字节的规则，例如 UTF-8 把 Unicode 码点映射为字节。Base64 是编码，不是加密；编码通常不需要秘密即可逆转。

### serialization（序列化）

把结构化对象编码为可存储或传输的字节，并规定字段、长度、顺序和错误处理。JSON、Protocol Buffers 与自定义二进制协议都是序列化方案。

### endianness（字节序）

多字节数值在内存或协议中的字节排列。小端把最低有效字节放在低地址；它不表示字符串反向，也不改变单个字节内部位序。

### signedness（有符号性）

决定某个位模式按非负整数还是含负数范围解释。`0xff` 作为 8 bit 无符号是 255，按 8 bit 补码有符号则是 -1。

### overflow（溢出）

结果超出目标类型可表示范围。不同语言规则不同：C 无符号回绕，有符号溢出可能是未定义行为，Python 整数一般自动扩展。不能脱离语言和位宽谈“溢出后的值”。

## 一个表示层次示例

```bash
printf 'A' | od -An -t x1
printf '41' | od -An -t x1
```

预期输出：

```text
 41
 34 31
```

字符 `A` 的 ASCII/UTF-8 字节是十六进制 `41`；文本 `41` 由字符 `'4'` 和 `'1'` 组成，字节是 `34 31`。这正是“十六进制显示”和“原始字节”不能混为一谈的原因。更多转换见 [数值与编码参考](./02-number-encoding-reference.md)。

## 操作系统与 Linux

### kernel / user space（内核态 / 用户态）

内核管理内存、调度、设备和权限；普通应用在受限用户态运行，通过系统调用请求服务。“用户态”不是指某个登录用户，而是 CPU 权限级与执行环境。

### process（进程）

正在运行程序的实例，拥有虚拟地址空间、文件描述符、身份和至少一个线程。可执行文件是静态磁盘对象，进程是运行时状态，两者不是同一个东西。

### thread（线程）

进程内可独立调度的执行流。线程通常共享地址空间和打开文件，因此并发访问共享数据需要同步；不同进程默认有隔离的虚拟地址空间。

### PID / PPID

PID 是进程编号，PPID 是父进程编号。PID 会复用，不能把很早记录的数字永久当作同一进程身份；shell 作业号 `%1` 也不是 PID 1。

### file descriptor（文件描述符，fd）

进程内指向打开内核对象的小整数句柄。fd 0/1/2 通常是标准输入/输出/错误；同一文件可被多个 fd 或进程引用。

### system call（系统调用）

用户态请求内核服务的受控入口，例如 `read`、`write`、`openat`。C 库函数可能包装一个或多个 syscall，也可能完全在用户态完成工作。

### signal（信号）

向进程或线程通知异步事件的机制。`SIGTERM` 可被处理以有序退出，`SIGKILL` 不能捕获且不给清理机会；信号不是普通函数调用。

### pipe（管道）

内核维护的字节流通道，常把一个进程的 stdout 接到另一个的 stdin。管道没有天然“行”概念，行是上层程序约定；普通 `|` 也不会自动传递 stderr。

### TTY / PTY

TTY 是终端接口的历史名称；PTY 是软件提供的伪终端对。SSH、终端模拟器和 tmux 常通过 PTY 给交互程序提供行规程、窗口大小与前台进程组语义。

### environment（环境）

创建新进程时继承的一组字符串键值，例如 `PATH`、`LANG`。环境来自父进程副本，可能影响程序行为，但不是可信配置或秘密存储机制。

### UID / GID

Linux 用数字用户与组标识参与权限判断，用户名只是映射。进程可能同时有真实、有效、保存的身份；文件元数据通常保存数字 UID/GID。

### permission / ACL

传统模式用 owner/group/other 的 `rwx` 位控制访问；ACL 可表达更细规则。最终访问还会受路径目录、挂载、capability 和安全模块约束，不能只看最后文件的 `ls -l`。

### inode / directory entry

inode 保存文件对象的元数据与数据位置，目录项把名字映射到 inode。删除一个名字不一定立即回收数据，因为其他硬链接或打开 fd 仍可能引用 inode。

### hard link / symbolic link

硬链接是另一个指向同一 inode 的目录项；符号链接是保存另一条路径文本的独立对象。符号链接解析受当前目录和路径环境影响，也可能引入竞态。

### CWD / PATH

CWD 是进程当前工作目录，相对路径以它为起点；`PATH` 是 shell 搜索无斜杠命令名的有序目录列表。两者都属于运行上下文，但解决不同问题。

### exit status（退出状态）

进程结束时返回给父进程的小整数；惯例上 0 成功、非零失败，具体含义由程序定义。它不是程序打印到 stdout 的文本。

```bash
sh -c 'exit 7'
status=$?
printf 'status=%d\n' "$status"
```

预期输出 `status=7`。状态必须立即保存，因为后续命令会覆盖 `$?`。

## 程序、二进制与内存

### ISA（指令集架构）

处理器对软件可见的指令、寄存器和执行语义，例如 x86-64、AArch64。ISA 不等于具体 CPU 微架构；同一 ISA 可有不同内部实现。

### ABI（应用二进制接口）

规定编译后二进制如何协作，包括调用约定、数据布局、对象格式和系统接口。API 是源码层接口，ABI 是二进制层契约。

### calling convention（调用约定）

ABI 中关于参数放哪里、返回值在哪、谁保存寄存器、栈如何对齐的规则。普通函数约定与 Linux syscall 约定不同，详见 [x86-64 附录](./03-x86-64-registers-and-syscalls.md)。

### register（寄存器）

CPU 可直接操作的少量高速状态，例如通用寄存器、指令指针和标志寄存器。寄存器“常见角色”来自 ABI 与指令语义，并非变量永久绑定。

### machine code / assembly

机器码是 CPU 执行的字节；汇编语言是其人类可读表示。反汇编从字节恢复指令文本，通常不能恢复原始变量名、注释和高级结构。

### ELF

Linux 等系统常用的可执行与可链接格式，可包含程序头、节、符号、重定位和调试信息。ELF 是文件格式，不保证文件可信，也不意味着必须执行才能分析。

### section / segment（节 / 段）

section 主要服务链接与静态组织，如 `.text`、`.rodata`、`.symtab`；segment 由程序头描述加载器映射到进程的区域。两者可能覆盖关系不同，不能按名称一一对应。

### symbol / relocation（符号 / 重定位）

符号把名字关联到地址或实体；重定位记录链接或加载时需要修正的位置。strip 可移除部分符号，但不会把机器代码变回“不可分析”。

### static / dynamic linking（静态 / 动态链接）

静态链接把所需实现更多地放入最终文件；动态链接在加载或运行时解析共享库。动态链接减小重复与便于更新，同时引入加载路径、版本和运行时解析问题。

### stack / heap

栈常用于调用帧、局部状态和返回控制；堆由分配器管理动态生命周期对象。二者都是进程虚拟内存区域，不应简单等同于“向下长”和“向上长”的固定物理结构。

### stack frame（栈帧）

一次函数调用的逻辑状态，包括返回位置、保存寄存器、局部数据等；优化器可省略传统帧指针或完全内联函数。调试器中的 frame 是恢复出的逻辑视图。

### pointer（指针）

在特定进程与地址空间中表示内存位置的值。地址不是对象的所有权或长度证明；解引用前仍需满足生命周期、对齐、映射和权限条件。

### virtual memory / page

虚拟内存让每个进程看到独立地址空间，内核以页为单位映射到物理内存或其他后端。地址连续不保证物理连续；页权限通常表达读、写、执行组合。

### ASLR / PIE

ASLR 随机化内存映射位置；PIE 让主可执行文件可被重定位，从而参与地址随机化。它们提高攻击不确定性，但不修复内存错误本身。

### NX / W^X

NX 允许页面标为不可执行；W^X 是内存不同时可写与可执行的策略。它们减少直接执行注入数据的机会，但不能阻止所有控制流或数据流攻击。

## 调试与分析

### debugger（调试器）

控制程序运行并观察状态的工具，例如 GDB。调试会改变时序，且修改变量、内存或指令指针的命令会主动改变目标。

### breakpoint / watchpoint

断点在执行到位置时停止；watchpoint 在某个内存值或访问事件发生时停止。硬件 watchpoint 数量有限，软件实现可能显著减速。

### backtrace

从当前函数沿调用关系恢复的栈帧序列。优化、损坏栈、异常控制流或缺少展开信息会让结果不完整。

### core dump

进程异常时保存的部分地址空间与状态快照，可供离线调试。它可能包含口令、密钥和个人数据，应按敏感数据保护。

### disassembly / decompilation

反汇编把机器码转换为汇编；反编译尝试重建高级伪代码。两者都是推断结果，需要与控制流、数据流和运行证据交叉验证。

## 安全概念

### vulnerability（漏洞）

系统设计或实现中可违反预期安全属性的缺陷。程序崩溃是证据之一，但并非每个崩溃都可利用，也并非所有漏洞都会崩溃。

### exploit / payload

exploit 是利用漏洞达到某种效果的方法或程序；payload 是其中承载的具体数据或后续动作。术语本身不构成授权，使用边界由目标所有权与明确许可决定。

### primitive（利用原语）

可重复、较小的能力，如“读取某地址若干字节”或“受限写入”。完整影响通常由多个原语、系统状态和权限条件组合而成。

### threat model（威胁模型）

明确资产、攻击者能力、信任边界、允许目标与不考虑事项的假设集合。没有威胁模型，“安全”无法转化为可检验命题。

### attack surface（攻击面）

不可信输入可触达的接口、代码和状态总和，包括网络端口、文件格式、插件、权限边界和供应链。减少接口不等于消除所有漏洞，但可缩小分析范围。

### authentication / authorization（认证 / 授权）

认证回答“你是谁”，授权回答“这个身份能做什么”。成功登录不表示能访问所有资源；缺一不可。

### least privilege（最小权限）

主体只获得完成任务所需的最小权限、范围与时间。它限制缺陷影响，但不能替代输入验证和安全设计。

### sandbox（沙箱）

通过系统调用、文件、网络、身份或资源策略约束程序。沙箱强度取决于具体边界和配置；容器、chroot、seccomp、VM 是不同机制。

### race condition / TOCTOU

竞态是结果依赖非预期时序；TOCTOU 是“检查时”和“使用时”状态可能变化的一类竞态。修复通常需要原子操作或持有稳定对象引用，而不是单纯缩短间隔。

### memory corruption

程序以不符合语言或对象边界的方式读写内存，包括越界、释放后使用和错误类型解释。具体影响取决于布局、控制数据和缓解机制。

### buffer overflow / out-of-bounds

buffer overflow 通常指写入超过缓冲区容量；out-of-bounds 还包括越界读取。修复要验证长度、整数计算和目标容量，不能只依赖崩溃防护。

### use-after-free（释放后使用）

对象生命周期结束后仍通过旧引用访问。分配器可能把同一区域交给其他对象，使旧引用读写新的语义对象。

### format-string vulnerability（格式字符串漏洞）

不可信输入被当作格式模板而不是普通数据。安全边界在“格式固定、数据作为参数”，例如 C 中使用 `printf("%s", user)` 而不是 `printf(user)`。

### ROP（返回导向编程）

利用已有代码片段和控制流转移组合行为的技术，常用于不可直接执行数据页面的环境。它依赖具体二进制、调用约定、地址与控制原语，不是一个跨目标固定模板。

## Web 与密码学常见词

### origin（源）

浏览器安全模型中通常由 scheme、host、port 三元组定义。路径不同不改变源，端口或协议不同会改变源。

### cookie / session

Cookie 是浏览器按规则随请求携带的小数据；session 是服务端或协议层维护的会话状态。Cookie 可保存 session 标识，但二者不等价。

### XSS / CSRF

XSS 使不可信内容在页面上下文执行脚本；CSRF 利用浏览器自动携带凭据诱导已登录用户发起请求。输出编码、CSP、SameSite、CSRF token 分别覆盖不同环节。

### SQL injection

不可信数据改变 SQL 语法结构。首要防护是参数化查询并配合最小数据库权限，而不是手工替换少数引号。

### encryption / hashing / MAC

加密用密钥提供机密性；哈希把任意输入映射为固定长度摘要；MAC 用共享密钥验证完整性与来源。三者目标不同，不能用普通哈希替代消息认证。

### nonce / IV / salt

nonce 通常要求在特定密钥上下文不重复；IV 的要求取决于算法模式；salt 让相同口令产生不同派生结果并阻碍预计算。它们通常可以公开，但必须满足各自生成规则。

## 最后提醒

术语是压缩后的模型。遇到真实代码时，应回到对象、状态、输入边界和适用平台验证，不要因为两个场景用了同一个词就假定机制完全相同。
