# 09 · 进程与作业

> 对应官方模块：[Processes and Jobs](https://pwn.college/linux-luminarium/processes/)

## 学习目标

- 区分进程、PID、作业和前台进程组。
- 理解 `&`、`jobs`、`fg`、`bg`、`wait` 与常见终端按键。
- 安全地等待或结束自己启动的进程。

## 进程与 shell 作业不是同一概念

进程是内核运行程序的实例，拥有 PID、地址空间、文件描述符和身份。作业是交互式 shell 对一个或多个相关进程的管理单位；一条管道可能包含多个进程，却作为一个作业显示。

终端通常把输入交给前台进程组。按 `Ctrl-C` 时，终端驱动向前台进程组发送 `SIGINT`；按 `Ctrl-Z` 通常发送 `SIGTSTP` 使其暂停。`fg` 把作业放回前台，`bg` 让暂停作业在后台继续。

## 安全示例：启动并回收后台进程

```bash
sleep 0.1 &
child_pid=$!
printf 'started pid=%s\n' "$child_pid"
wait "$child_pid"
printf 'child exit=%d\n' "$?"
```

预期输出形态：

```text
[1] 12345
started pid=12345
child exit=0
```

`&` 让命令在后台运行；`$!` 是最近后台管道的 PID；`wait` 阻塞到指定子进程结束并返回其状态。PID 每次不同，且 shell 的作业提示格式可能不同。

观察当前 shell 及其子进程可用：

```bash
ps -o pid,ppid,stat,comm -p "$$"
```

`$$` 是当前 shell PID；`PPID` 表示父进程；`STAT` 展示运行、睡眠或暂停等状态。

## 信号不是“强制删除”

`kill PID` 默认发送 `SIGTERM`，请求进程有序终止；程序可以处理或暂时阻塞它。`SIGKILL` 无法捕获，但也不给程序清理机会，应作为最后手段。发送前必须确认 PID 属于目标进程；PID 会复用，陈旧记录可能指向另一个进程。

## 常见误区

- **认为后台进程不再输出。** 它仍可能连接同一终端，造成混杂输出。
- **把作业号 `%1` 与 PID `1` 混淆。** 前者由当前 shell 管理，后者是内核进程号。
- **一律使用 `kill -9`。** 会跳过正常清理，并掩盖真正的停止问题。
- **认为关闭终端总会杀死进程。** SIGHUP、会话、复用器和程序处理方式都会影响结果。

## 纸面练习

一条后台管道 `producer | consumer &` 为什么可能显示一个作业号却包含两个 PID？`wait` 的作用是什么？

### 答案

shell 把整条相关管道作为一个作业管理，但管道两端是独立进程，所以有各自 PID。`wait` 让 shell 等待后台子进程或作业完成，并取得退出状态，避免脚本在结果尚未产生时继续。

## 小结

内核管理进程，交互式 shell 在其上管理作业和前台进程组。理解 PID、进程组、信号和等待关系，才能可靠控制并发任务而不误伤其他进程。
