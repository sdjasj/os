# 15 · Shell 环境里的隐蔽边界

> 对应官方模块：[Silly Shenanigans](https://pwn.college/linux-luminarium/shenanigans/)

## 学习目标

- 理解 shell 启动文件为什么属于代码执行边界；
- 解释终端输入、进程参数和配置文件怎样意外泄漏信息；
- 识别共享目录、符号链接与可预测文件名带来的替换风险；
- 建立“秘密不进入可观察通道、可信代码不可被低权限方修改”的习惯。

本章讲的是防御性观察。示例只查看当前用户自己启动的进程和自己创建的临时目录，不演示后门、键盘记录或窃取其他用户数据。

## 1. Bash 启动文件是自动执行的代码

Bash 根据启动方式读取不同文件，例如登录 shell 可能读取 profile 类文件，交互式非登录 shell 通常读取 <code>~/.bashrc</code>。这些文件不是普通“主题配置”：其中可以执行任意 shell 命令、定义函数、修改 PATH、别名和环境变量。

信任链为：

~~~text
启动 shell
  -> 定位启动文件
  -> 按当前用户权限读取
  -> 把文件内容当 shell 程序执行
  -> 新会话继承其环境和函数
~~~

因此，若其他用户能写你的启动文件或其父目录，就可能影响你下一次打开终端时执行的代码。检查自己的文件：

~~~bash
ls -ld -- "$HOME"
for startup in "$HOME/.profile" "$HOME/.bash_profile" "$HOME/.bashrc"; do
    if test -e "$startup"; then
        stat -c '%A %U:%G %n' -- "$startup"
    fi
done
~~~

预期输出因系统而异，关键是不应由不受信任用户或宽泛组拥有写权限。若怀疑启动配置有问题，可启动一个不读取 profile/rc 的干净 Bash 做诊断：

~~~bash
env -i HOME="$HOME" TERM="$TERM" PATH=/usr/bin:/bin \
    bash --noprofile --norc
~~~

这里 <code>env -i</code> 清空继承环境，再显式提供最小变量。它是诊断入口，不会自动修复已被篡改的文件。

### 审计启动文件

只读检查应关注：

- 未知的 source 或点命令；
- 从临时目录、共享目录加载脚本；
- PATH 前部加入可写目录；
- 覆盖 cd、sudo、ssh 等常用名字的函数/别名；
- 在提示符命令、退出钩子或补全逻辑中执行外部程序；
- 把令牌、历史记录或输入发送到网络的命令。

不要看到陌生行就直接删除。先保留副本、确认它属于软件安装还是人工配置，再从可信介质恢复。

## 2. 终端输入经过哪些组件

键盘内容并不是直接送到 Bash：

~~~text
键盘
 -> 终端模拟器
 -> 伪终端 master/slave
 -> 内核 tty 行规程
 -> 前台进程组
 -> read/readline
~~~

终端通常回显普通字符。密码输入程序会暂时关闭 echo，所以屏幕不显示字符；这只防止旁观者看屏幕，不代表输入从系统中“不可观察”。被攻陷的终端模拟器、同权限调试能力、高权限进程或恶意输入法仍可能看到输入。

可安全观察自己的终端设置：

~~~bash
stty -a | tr ';' '\n' | sed -n '1,8p'
~~~

若编写交互脚本，退出和信号路径也必须恢复终端状态。Bash 的 <code>read -s</code> 可关闭本次输入回显，但不要把它描述为安全秘密存储。

### 输入为什么不应进入日志

开启 <code>set -x</code> 会把展开后的命令打印到标准错误；CI 日志、终端录制和 shell 历史可能因此保存密码。更稳妥的设计是：

- 使用专用凭据文件描述符或系统密钥存储；
- 给秘密文件最小权限；
- 在调试日志中只记录“凭据已提供”，不记录值；
- 不把秘密拼进命令行；
- 在错误报告和截图前做脱敏。

## 3. 进程参数是一条可观察通道

命令行参数常被 <code>ps</code>、<code>/proc/PID/cmdline</code>、服务管理器和崩溃报告记录。下面只观察自己启动的、带虚构参数的进程：

~~~bash
python3 -c 'import time; time.sleep(2)' 'DEMO_TOKEN=not-a-secret' &
demo_pid=$!
tr '\0' ' ' < "/proc/$demo_pid/cmdline"
printf '\n'
wait "$demo_pid"
~~~

预期输出包含：

~~~text
python3 -c import time; time.sleep(2) DEMO_TOKEN=not-a-secret
~~~

权限策略可能限制其他用户读取，但同一用户的进程、监控代理或高权限管理员通常仍可见。因此密码、API token、私钥内容不应作为 argv。

更好的传递方式取决于应用：

- 由权限受限的文件读取；
- 从标准输入或继承的匿名管道读取；
- 通过操作系统密钥环或 secrets manager 获取；
- 传递已打开文件描述符；
- 使用短期、最小权限凭据并支持轮换。

环境变量也不是万能秘密通道；它们会被子进程继承，可能进入诊断、转储或同权限观察接口。

## 4. 共享目录与可预测名字

多人可写目录允许其他用户创建、重命名或删除目录项。<code>/tmp</code> 通常带 sticky bit：

~~~bash
stat -c '%A %a %n' /tmp
~~~

典型模式末尾为 <code>t</code>，数字模式含 1000。sticky bit 限制普通用户删除不属于自己的条目，但不会让可预测文件名自动安全，也不会消除符号链接和内容信任问题。

安全创建临时对象：

~~~bash
private_dir=$(mktemp -d)
umask 077
printf 'tutorial data\n' > "$private_dir/note.txt"
stat -c '%a %n' "$private_dir" "$private_dir/note.txt"
rm -r -- "$private_dir"
~~~

预期目录和文件仅当前用户可访问，具体模式通常分别为 700 与 600。不要采用“先判断文件不存在，再用固定名字创建”的流程；检查和创建之间可以被另一进程抢占。应使用 <code>mkstemp</code>、<code>mkdtemp</code> 或 <code>open</code> 的 O_CREAT|O_EXCL。

## 5. 符号链接为何会让路径检查失效

符号链接保存的是另一条路径。内核解析名字时可能跟随它：

~~~text
程序检查 /shared/report
       |
       v
另一进程把 report 换成符号链接
       |
       v
程序再次打开同名路径，却得到另一个对象
~~~

这类检查—使用分离称为 TOCTOU。安全原则：

- 不对同一路径先 access/stat 再 open；
- 从可信目录文件描述符出发使用 openat/openat2；
- 在需要时使用 O_NOFOLLOW，并理解它通常只约束最后分量；
- 打开后用 fstat 检查同一个文件描述符；
- 创建时使用原子排他选项；
- 不让攻击者控制中间目录；
- 对敏感路径使用最小权限和独立目录。

硬链接与符号链接不同：硬链接是同一 inode 的另一个目录项，不能简单用“最终字符串不含 ..”处理所有引用问题。

## 6. 配置文件也可能泄漏或执行

配置的风险不只在“密码写在明文里”。解析器可能支持：

- include 其他文件；
- 变量替换；
- 命令执行或插件加载；
- 相对路径；
- 从当前目录或 HOME 自动发现；
- 宽泛权限下的覆盖。

一个只保存虚构数据的安全示例：

~~~bash
config_dir=$(mktemp -d)
umask 077
printf '%s\n' 'endpoint=http://127.0.0.1:9000' \
    'token=DEMO-ONLY' > "$config_dir/app.conf"
stat -c '%a %U:%G %n' "$config_dir/app.conf"
rm -r -- "$config_dir"
~~~

预期文件模式为 600。生产服务还应：

- 使用固定、可信的绝对配置路径；
- 让服务账户只读而不能修改安全策略；
- 把长期密钥放入专用秘密存储；
- 禁止或白名单 include/plugin；
- 不在错误消息中回显完整配置；
- 定期轮换泄漏过的凭据。

## 7. 调查时保持证据

发现异常 shell 配置、未知进程或可疑链接时：

1. 先断开可能的外部访问并保护账号；
2. 记录时间、文件元数据、哈希和进程信息；
3. 不用被怀疑已受控的 shell 执行高价值凭据操作；
4. 从可信环境检查启动文件、计划任务和授权密钥；
5. 轮换可能暴露的凭据；
6. 若无法证明系统完整性，从可信镜像重建。

只删除一行可疑配置不能证明攻击者没有建立其他持久化。

## 常见误区

- **启动文件只是外观设置。** 它们是会自动执行的程序。
- **密码不回显就无人能观察。** 回显只是终端显示属性。
- **同一用户的进程互相信任。** 浏览器、编辑器插件和构建任务可能处于不同信任级别。
- **/tmp 有 sticky bit 就可安全使用固定名字。** 创建、链接和内容替换仍需原子接口。
- **隐藏进程参数即可把秘密放环境变量。** 环境也会继承和泄漏。
- **配置文件 chmod 600 就没有风险。** 解析能力、备份、日志和运行账户仍需审计。

## 纸面练习

### 题目一

备份脚本把数据库密码作为 <code>--password=...</code> 参数传给客户端，执行时间只有一秒。为什么仍不安全？

### 答案

暴露窗口虽短但真实存在，参数还可能被进程监控、审计日志、服务管理器或错误报告捕获。应使用客户端支持的受限凭据文件、匿名管道或密钥代理，并避免把值打印到日志。

### 题目二

程序先用 <code>stat(path)</code> 确认所有者，再用 <code>open(path)</code> 读取。问题是什么？

### 答案

两次路径解析可能得到不同对象。攻击者可在中间替换目录项或链接。应先安全打开，再用 <code>fstat(fd)</code> 检查并通过同一 fd 使用。

### 题目三

为什么以 <code>bash --noprofile --norc</code> 启动成功，不能证明整个账号环境安全？

### 答案

它只绕过 Bash 的部分启动文件。终端模拟器、环境变量、SSH 配置、计划任务、编辑器插件、二进制 PATH 和系统级启动配置仍可能受影响；需要更广的可信环境调查。

## 小结

Shell 环境中的“便利机制”经常也是信任边界：启动文件会执行，TTY 承载输入，argv 与环境会被观察，共享目录允许名字重新绑定，配置解析器可能加载更多内容。防御的共同原则是收紧写权限、使用原子对象句柄、让秘密远离可观察通道，并在异常后从可信环境恢复。
