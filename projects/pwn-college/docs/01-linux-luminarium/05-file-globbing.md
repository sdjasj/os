# 05 · 文件通配

> 对应官方模块：[File Globbing](https://pwn.college/linux-luminarium/globbing/)

## 学习目标

- 理解 `*`、`?`、字符集合和排除字符类的匹配语义。
- 知道通配通常由 shell 在启动程序前展开。
- 识别空匹配、隐藏文件和特殊文件名带来的风险。

## 展开发生在程序之前

输入 `printf '%s\n' *.txt` 时，Bash 先在当前目录查找匹配名字，再把每个结果作为独立参数传给 `printf`。常见模式包括：

- `*`：匹配任意长度字符串，但默认不跨 `/`。
- `?`：匹配恰好一个字符。
- `[ab]`：匹配集合中的一个字符。
- `[0-9]`：匹配指定范围内的一个字符，受区域设置影响。

把模式放进引号会阻止展开：`"*.txt"` 是六个字面字符。

## 安全示例：在专用目录观察参数

```bash
glob_dir=$(mktemp -d)
touch "$glob_dir/report1.txt" "$glob_dir/report2.txt" "$glob_dir/notes.md"
printf '%s\n' "$glob_dir"/report?.txt
rm -r -- "$glob_dir"
```

预期输出形态：

```text
/tmp/tmp.xxxx/report1.txt
/tmp/tmp.xxxx/report2.txt
```

变量部分被引用以保持路径整体，变量后的 `/report?.txt` 没有被引用，因此仍会通配。这种“引用变量、保留明确模式”的写法比不加引号的 `$glob_dir/report?.txt` 更稳健。

默认 Bash 中，开头的 `*` 不匹配点文件；模式无匹配时通常原样保留。脚本若依赖其他行为，应显式设置并理解 `nullglob`、`failglob` 或 `dotglob`，不要假定所有 shell 相同。

## 排除字符类：`[!...]` 与 `[^...]`

字符类开头的 `!` 表示“匹配集合之外的一个字符”。例如 `[!0-9]` 匹配一个非数字字符，而不是“任意长度的非数字文本”。Bash 也接受 `[^0-9]`，但在 shell glob 中 `[!...]` 是更传统、可移植的写法；`!` 或 `^` 只有出现在开方括号之后的特殊位置才表示排除。

下面创建三份自有空文件，再只选择文件名首字符不是数字的两份：

```bash
exclude_dir=$(mktemp -d)
touch "$exclude_dir/a.txt" "$exclude_dir/b.txt" "$exclude_dir/1.txt"

(
  cd "$exclude_dir" || exit 1
  printf '%s\n' [!0-9].txt | LC_ALL=C sort
)

rm -r -- "$exclude_dir"
```

预期输出：

```text
a.txt
b.txt
```

模式 `[!0-9].txt` 的字符类只占一个字符位置，所以它匹配 `a.txt`、`b.txt`，排除 `1.txt`，也不会匹配 `report.txt`。与其他 glob 一样，展开仍发生在启动 `printf` 之前；若目录中没有匹配项，Bash 默认可能把模式原样传入程序。

排除字符类也不会改变点文件规则。模式的第一个字符若不是显式的 `.`，默认仍不会匹配以点开头的名字。

## 安全视角

通配展开结果取决于目录当时的内容，可能出现竞态或意外参数。尤其不要把不受控目录中的 `*` 直接交给会解释选项的程序；恶意文件名可能以 `-` 开头。支持时用 `--` 结束选项，并优先使用 `find ... -exec` 等能明确传递边界的接口。

## 常见误区

- **认为程序自己读取 `*`。** 多数普通命令收到的是展开后的文件名列表。
- **认为 `*` 包含隐藏文件。** 默认不会匹配以 `.` 开头的名字。
- **无匹配时必然得到空列表。** Bash 默认可能保留字面模式。
- **用 `ls` 输出继续解析文件名。** 文件名可含空格和换行，显示文本不是可靠数据格式。

## 纸面练习

目录中有 `a1.log`、`a2.log`、`ab.log`、`.a3.log`。默认 Bash 下，模式 `a[0-9].log` 匹配哪些？

### 答案

匹配 `a1.log` 和 `a2.log`。`ab.log` 的中间字符不在数字范围；`.a3.log` 以点开头，而且整体结构也不符合模式起始位置。

## 小结

通配是 shell 的参数生成机制。理解展开时机、引用边界和目录内容的影响，才能在批量处理文件时既准确又安全。
