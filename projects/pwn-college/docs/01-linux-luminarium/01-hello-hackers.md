# 01 · 你好，命令行

> 对应官方模块：[Hello Hackers](https://pwn.college/linux-luminarium/hello/)

## 学习目标

- 区分终端、shell 与被启动的程序。
- 理解一条简单命令从文本变为进程的基本路径。
- 学会观察当前身份与 shell 的命令解析结果。

## 三个容易混淆的角色

**终端**负责输入和显示；**shell**（如 Bash）读取命令文本，处理引号、变量和重定向；**程序**接收已经解析好的参数并执行工作。输入 `id -u` 时，终端把字符交给 Bash，Bash 找到 `id` 程序并传入一个参数 `-u`，最后终端显示程序写出的结果。

```text
键盘 → 终端 → Bash 解析 → 启动 id("-u") → 标准输出 → 终端
```

这种分工很重要：`*` 是否展开、`>` 是否改写文件，通常由 shell 决定；`id` 并不会看到原始命令行中的这些符号。

## 安全示例：认识当前会话

```bash
printf 'shell=%s\n' "$SHELL"
id -u
id -un
```

预期输出形态：

```text
shell=/bin/bash
1000
alice
```

`id -u` 给出数字 UID，`id -un` 把同一身份解析为用户名。具体数值和名字因系统而异。`printf` 是比 `echo` 更可预测的格式化输出工具：格式串固定为 `shell=%s\n`，值通过 `%s` 插入。

可以用 `type` 判断命令由谁提供：

```bash
type printf
type id
```

Bash 中常见输出是 `printf is a shell builtin`，而 `id is /usr/bin/id`。内建命令直接由 shell 实现，外部命令通常需要启动新进程。

## 常见误区

- **把终端当成 shell。** 终端窗口关闭是界面事件，命令语法来自其中运行的 shell。
- **认为每个命令都是文件。** `cd`、`printf` 等可由 shell 内建实现。
- **照抄输出中的用户名或 UID。** 它们是当前系统状态，不是固定答案。
- **默认使用 root。** 学习普通命令无需管理员权限，最小权限能减少误操作影响。

## 纸面练习

若 `type cd` 显示 `cd is a shell builtin`，为什么 `cd` 通常不能只做成一个外部程序来改变当前 shell 的目录？

### 答案

外部程序运行在独立进程中，只能改变自己的当前目录；它退出后，父 shell 的状态不会随之改变。作为 shell 内建，`cd` 才能直接修改当前 shell 进程保存的工作目录。

## 小结

命令行由终端、shell 和程序协作完成。先判断某个行为发生在哪一层，后续理解引号、通配符、管道和权限时就不会把责任归错对象。
