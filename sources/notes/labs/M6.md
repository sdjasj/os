## 1\. 背景

GPT (Generative Pre-trained Transformers) 系列模型开启了人工智能的新时代。从聊天机器人到多模态模型、Agentic AI，再到具身智能，大语言模型是人类进入新纪元的起点。“大语言模型” 本质上是一个函数 <span class="katex"><span class="katex-mathml">\(f\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8889em;vertical-align:-0.1944em"></span><span class="mord mathnormal" style="margin-right:0.10764em">f</span></span></span></span>，能够接收 “一串文本”，输出 “文本可能的下一个字符”。这个 “智能” 函数 <span class="katex"><span class="katex-mathml">\(f\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8889em;vertical-align:-0.1944em"></span><span class="mord mathnormal" style="margin-right:0.10764em">f</span></span></span></span> 具有惊人的应用场景，包括 “一切” 的 copilot (编程、操作系统使用、甚至是课堂学习)，和可以各种替代人类的智能 agent。“多模态” 模型甚至可以将文本、图像、声音、触觉等对齐到语言模型训练的向量上，实现与人类类似的 “智能”。

而 <span class="katex"><span class="katex-mathml">\(f\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8889em;vertical-align:-0.1944em"></span><span class="mord mathnormal" style="margin-right:0.10764em">f</span></span></span></span> 训练好之后，会在云端 (超级计算机) 或端侧 (手机、手表……) 部署，以 API 的形式提供服务。正如我们所预见的，AI 推理服务已经和水、电、云一样，成为人类社会的重要基础设施。我们不断看到 Richard Sutton's [Bitter Lesson](../../manuals/bitter_lesson.pdf) 在生效：与 “精雕细琢” 的启发式方法相比，真正能利用好算力和数据的机制才是最终制胜的关键。

## 3\. 正确性标准

<span class="float-left text-4xl mr-3 mt-2">🗒️</span><span class="font-serif text-lg border-b border-slate-600">**正确性 & Scalability**</span>

你并行化后的**程序行为**应当与我们给出的串行程序保持严格一致 (如果你希望动手 “玩一玩”，可以直接移步原 repo)。例如，我们输入 + 输出总共 <span class="katex"><span class="katex-mathml">\(n = 10\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.4306em"></span><span class="mord mathnormal">n</span><span class="mspace" style="margin-right:0.2778em"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em"></span></span><span class="base"><span class="strut" style="height:0.6444em"></span><span class="mord">10</span></span></span></span> 个 tokens。你应该保持这个行为不变。

并行化带来的计算顺序调整可能会轻微影响整个神经网络的激活函数函数值，但只要最终输出的 token 序列 (理解为文本) 一致，我们就认为正确。相比于串行程序，在一个 <span class="katex"><span class="katex-mathml">\(k\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.6944em"></span><span class="mord mathnormal" style="margin-right:0.03148em">k</span></span></span></span> 个处理器的计算机上，除去模型加载时间，你应当在有较多轮推理时得到近似线性 (<span class="katex"><span class="katex-mathml">\(k\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.6944em"></span><span class="mord mathnormal" style="margin-right:0.03148em">k</span></span></span></span> 倍) 的加速比。

Online Judge 评测时，<span class="katex"><span class="katex-mathml">\(k \leq 4\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8304em;vertical-align:-0.136em"></span><span class="mord mathnormal" style="margin-right:0.03148em">k</span><span class="mspace" style="margin-right:0.2778em"></span><span class="mrel">≤</span><span class="mspace" style="margin-right:0.2778em"></span></span><span class="base"><span class="strut" style="height:0.6444em"></span><span class="mord">4</span></span></span></span>。对于真实的神经网络训练/推导系统，GPU 这类 SIMT 的大规模并行处理器在能耗比上相比 CPU 有巨大的优势。回顾课程中讲解 SIMT 时，一个线程束共享一个 Program Counter，控制多个线程 “同步” 执行指令。此时，针对大矩阵、向量的 load/store，一个线程束就会生成一个非常长的内存 load (coalesced memory access)。GPU 也为这样的内存访问模式做出了特别的优化——相比 CPU 对 “逻辑程序” 设计的 memory hierarchy，具有高得多的电路比和能效比。

在这个实验中，你需要静态分配好线程 (例如 4 个 workers)，然后由这些线程完成计算任务。Online Judge 测试时的线程库与同学们实验代码中的完全一样。

## 4\. 实验指南

### 4.1 GPT-2 工作原理

首先，gpt.c 的源代码就是最好的老师！它实现了对神经网络的 “真正数学严格” 的描述——如果我们看 PyTorch 的代码，其中会涉及许多内置的算子，你对其中的实现其实并不 100% 理解——但对于 C 代码这种语义 “扁平” 的语言来说，你真的可以完全理解它！此外，我们给一个[外链](https://jalammar.github.io/illustrated-gpt2/)，也还推荐 [Understanding Deep Learning](https://udlbook.github.io/udlbook/)。我也让 AI 在合适的提示词下对 gpt.c 做了一些总结：

整个程序可以理解为一台机器：你喂给它一段数字序列，它就吐出 “下一个最可能出现的数字”。然后把这个新数字塞回去，再算下一个，如此反复——这就是所谓的自回归生成。模型不认识文字，只认识数字。一段文本在进入模型之前，已经被切分成了一个个整数 id（称为 token）。比如 “hello world” 可能变成 `[31373, 995]`。模型的任务是：给定一串整数，预测下一个整数是什么：

  - 第一步：把整数变成向量。一个整数本身没有结构信息。模型的第一步是通过查表把每个整数变成一个浮点数向量（比如 768 维）。同时，每个位置（第 0 个、第 1 个……）也有一个对应的 “位置向量”。把两者加在一起，就得到了既包含 “这个词是什么” 又包含 “它在第几个位置” 的信息。这一步完全是查表加法，非常快。
  - 第二步：通过 L 层相同的 “处理模块”。接下来数据要经过 L 个完全相同的处理层。每一层做两件事：
      - 第一件事——让序列中的位置互相 “通信”。 一个词的意思往往取决于上下文。"bank"到底是银行还是河岸？你得看前后的词。这一步的操作可以理解为：每个位置生成一个 “问题”（Q）、一个 “钥匙”（K）、一个 “答案”（V），然后用问题去匹配所有不超过当前位置的钥匙，匹配度越高，就越采纳那个位置的答案。这保证了模型只能 “看到过去”，不能偷看未来——毕竟我们在预测未来。这一步的数学本质就是向量内积、指数函数、加权求和，全是初等运算。
      - 第二件事——让每个位置独立地做一次非线性变换。 通信完成后，每个位置拿着自己的信息，经过一个 “升维→激活→降维” 的过程。你可以把它理解为一个函数 <span class="katex"><span class="katex-mathml">\(f(x)\)</span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:1em;vertical-align:-0.25em"></span><span class="mord mathnormal" style="margin-right:0.10764em">f</span><span class="mopen">(</span><span class="mord mathnormal">x</span><span class="mclose">)</span></span></span></span>，先把输入展开到更高维（4 倍），过一个非线性函数（GELU，一个平滑的、类似 “如果为负就趋近零” 的函数），再压缩回原来的维度。这一步给模型提供了 “表达能力”——没有非线性变换，再多层叠起来等价于一层的线性变换。
      - 每一件事做完后，都有一个残差连接：把模块的输入直接加到输出上。这就像一条高速公路旁的辅路——信息可以跳过这个模块直接流过去，防止信息在层层 传递中逐渐消失；每一件事开始前，都会做一次 LayerNorm：把向量归一化为均值 0、方差 1，再缩放平移。这保证了数值在整个流程中不会爆炸或消失。
  - 第三步：从向量回到整数。L 层处理完后，最后再做一次 LayerNorm，然后把这个 768 维向量通过一个矩阵乘法，映射成 50257 维的向量（50257 是词表大小，即所有可能 token 的数量）。这个 50257 维向量中的每个数可以理解为一个"得分"——得分越高，对应的 token 就越可能是下一个词。经过 softmax（指数归一化）后，这些得分就变成了概率：所有值在 0 到 1 之间，加起来等于 1。
  - 第四步：采样，然后循环。程序在概率分布上采样（这里用的是中位数采样——总是选累积概率刚好过 0.5 的那个 token），得到一个整数。然后把这个新整数追加到输入序列末尾，重复整个过程，直到生成了足够多的 token。

从系统视角看，每次生成都要对整个序列重新计算一遍前向传播——第 1 步生成长度 5 的序列，第 2 步就要算长度 6 的序列，第 3 步算长度 7……这就是朴素自回归推理的计算瓶颈。代码中所有张量通过一次 malloc 分配，矩阵乘法是三重循环的朴素实现，没有任何外部库依赖。这个教学实现用最直白的方式展示了 “预测下一个 token” 这件事从头到尾到底发生了什么。

### 4.2 寻找并行的机会

如何优化你的代码？在开始任何优化之前，首先看 D. E. Knuth 的名言：

> Premature optimization is the root of all evil.

“Premature” 不仅指你不应该在实现代码的过程中做 “任意” 的优化，它们可能收效甚微，但大幅破坏了你代码的可读性、可维护性等。“Premature” 同样指你不应该随意地去动你的代码，然后去做一些想当然的优化。同样，这些优化可能破坏可读性，而且很可能没有什么效果。

根据二八定律，绝大部分的时间应该是消耗在少部分操作上的。因此，你首先需要理解程序的哪个部分消耗了最多的时间——针对性地，我们也应当试图优化 (并行化) 这些代码——你对占用 1% 时间的代码，即便优化到极致使运行时间完全为 0，你的收益也近乎为零。

当然，你需要工具：profiler，用于采样程序的运行时状态，“密集” 的采样就能得到程序消耗时间的序列。

> In [software engineering](https://en.wikipedia.org/wiki/Software_engineering), **profiling** ("program profiling", "software profiling") is a form of [dynamic program analysis](https://en.wikipedia.org/wiki/Dynamic_program_analysis) that measures, for example, the space (memory) or time [complexity of a program](https://en.wikipedia.org/wiki/Computational_complexity_theory), the [usage of particular instructions](https://en.wikipedia.org/wiki/Instruction_set_simulator), or the frequency and duration of function calls. Most commonly, profiling information serves to aid [program optimization](https://en.wikipedia.org/wiki/Program_optimization).

例如，Linux perf 工具是一个强大的性能分析工具，它提供了一系列用于分析程序性能和跟踪系统事件的功能。这个工具是内核中的一部分，利用了 Linux 内核中的性能计数器子系统。Perf 可以帮助开发者和系统管理员监控整个系统的性能，包括硬件和软件层面。Perf 工具能够测量软件事件如函数调用和程序执行时间，并且能够监控硬件事件比如 CPU 周期数、指令数以及缓存命中和未命中的情况。这使得它非常适合于性能调优和寻找瓶颈。此外，perf 支持事件的实时追踪，能够记录和报告系统运行中的各种事件，如上下文切换、系统调用、页错误等。这些功能使得 perf 成为 Linux 系统性能分析和问题诊断的重要工具。
